# Базовый спрайт Ash Warden

6 ноября 2026 года. Рекомендую [основной спрайт128×128](../../art/final-boss/ash-warden-base-final.png) как рабочую основу для дальнейшей анимации после ручной приёмки south idle. Он сохраняет двуручный хват, массивную обугленную броню, светящийся визор, лавовые разломы, корни, умеренные сухие ветви и рваную ткань.

Это один статичный персонаж с прозрачностью. Восемь направлений, анимации и интеграция в игру не выполнялись. Есть только один [запасной вариант](../../art/final-boss/ash-warden-base-alt.png): другая пиксельная подготовка того же мастера, без новой генерации дизайна. Он мягче, поэтому основным выбран более контрастный вариант PixelLab.

## Референсы и короткий аудит

Актуальные материалы найдены по прежним путям, структура не менялась:

- [Утверждённый концепт2](../../art/references/ash-warden-concept-02.png),1086×1448: основа шлема, визора, тяжёлой брони, разломов, корней и клинка.
- [Принятый как черновая основа кандидат](../../art/generated/ash-warden-base-01/ash-warden-base-candidate.png),128×128: south/front и игровой масштаб; прежние тонкий меч и одноручный хват целенаправленно заменены.
- [Предыдущий отчёт](BASE_SPRITE_01.md),PIXELLAB_AUDIT.md,результаты и comparison sheet в art/generated/ash-warden-base-01.
- public/assets/hd/mage.png+mage.json и ash-guard.png+ash-guard.json: реальные текущие кадры Mage и временного Стража для сравнения. Их масштабы проверены по assetRegistry.ts,камера — по GameScene.ts.

Aseprite MCP отвечает,но status вновь показывает executable=null,batch=unavailable,live.connected=false,extensionInstalled=false. Поэтому установки,изменения Windows,правки через неработающий редактор и экспорт.aseprite не выполнялись. По разрешённому fallback применены image_gen,PixelLab conversion и бесплатный pixelart_workbench.

## Что изменено

| Требование | Полученный результат |
| --- | --- |
| Массивный силуэт | Широкие плечевые плиты,тяжёлый грудной блок,толстые предплечья,короткие бронированные ноги |
| Чёрно-угольная броня | Тёмные плоскости с холодными стальными гранями вместо обычного рыцарского доспеха |
| Лавовые трещины | Оранжевые разломы на плечах,груди,предплечьях и широком клинке |
| Узкий визор | Светящаяся щель под закрытой расколотой короной шлема,без человеческих глаз |
| Сухие ветви | Небольшие древесные ответвления за плечами;не превращены в большие рога |
| Корни и ткань | Корни оплетают плечи,руки и часть ног;пепельные рваные полотнища обрамляют меч |
| Двуручный меч | Широкий тяжёлый клинок перед корпусом,две кисти друг над другом на одной рукояти,гарда ниже обеих рук |
| Low top-down / south | Фронтальная нейтральная стойка,видны верхние плоскости шлема/плеч и укороченные ноги |

Главное отличие от прошлого кандидата — новая конструкция рук и оружия. Левая и правая руки сходятся перед животом к общему хвату;свободной висящей руки нет. Это проверено на исходном мастере,увеличении128PNG и отдельном крупном фрагменте хвата. Ветви отделены от металлического профиля шлема,а светящиеся линии распределены по броне,не заменены одним воротом.

## Генерации и обработка

| Операция | Количество | Расход PixelLab |
| --- | ---: | ---: |
| Встроенный image_gen с двумя локальными референсами,transparent_background=true |1вызов,один дизайн |0 |
| PixelLab image_to_pixelart,faithful=true,init_image_strength150,128×128,seed260110611 |1вызов |1генерация |
| PixelLab pixelart_workbench:выделение фона flood_fill |1точная операция,13228пикселей |0 |
| PixelLab pixelart_workbench:закрытые просветы patch_pixels |1точная операция,10пикселей |0 |
| PixelLab pixelart_workbench:общая палитра map_colors |1точная операция,1698пикселей |0 |
| Запасной вариант из того же мастера |1локальная подготовка,без нового дизайна |0 |

На этом этапе PixelLab37→36remaining,3→4used. Исторические3генерации прошлого этапа повторно не считаются. Итого новых генеративных вызовов2:один image_gen и один PixelLab;это разные инструменты и единицы учёта. Платных PixelLab animation/direction/edit/regeneration calls не было. Бесплатные inspect/describe использованы для проверки и точных правок.

Дешёвые PixFlux-прогоны прошлого этапа не повторялись. На этот раз image_gen сначала сформировал правильные пропорции и двуручный хват по утверждённому концепту и черновику. Получен мастер1254×1254 с прозрачностью. Перед conversion он дополнен прозрачными полями до1536×1536 без изменения его пикселей:позиция(141,141). Это обеспечивает место для клинка и небольших ветвей на конечном холсте.

PixelLab conversion сохранил форму,но выдал полностью непрозрачный фон#818282. Бесплатная точная правка удалила весь связанный фон и10его пикселей в закрытых просветах,затем свела69цветов персонажа к32существующим цветам. Дизеринг,размытие и масштабирование native128PNG не применялись. Решения и ожидаемые цвета сохранены в work/pixel-cleanup.json.

У image_gen нет доступного seed;сохранены точный prompt,оба пути референсов и сам мастер. Поэтому воспроизводимой является пиксельная обработка сохранённого мастера,а не обещание побитового повторения генерации. Для PixelLab сохранены seed,request,receipt,job ID,gallery asset ID,upload ref и download URL. Подписанные upload URL и API-ключи в материалы не включены.

## PNG и сравнение в игровом масштабе

Основной PNG проверен декодированием пикселей:

- 128×128 RGBA; 3146 непрозрачных и 13238 прозрачных пикселей.
- Ровно 32 непрозрачных RGB цвета; alpha только 0/255, полупрозрачных пикселей 0.
- Bbox (37,21)–(90,109), 54×89; он включает ветви и клинок и не равен высоте тела.
- Непрозрачных пикселей на краях 0, остатков конвертерного серого фона 0.
- Весь силуэт соединён в один компонент по 8 соседям; отдельных случайных частиц нет.

Тело измерено в визуально выбранных областях шлема и ботинок:верх21,низ100,примерно80source px без нижней части меча. При scale0.908578125 это72.68625world px. Видимая высота текущего Mage71×0.375=26.625world px;отношение около2.73. Это ориентир для принятого рисунка,не вывод hitbox из PNG. Предлагаемая опора ног —(64,101),origin(0.5,101/128). Эти значения пока записаны только в base-metadata.json,игровой реестр не менялся.

## Проверки и ограничения

Проверки прошли: pixel QA обоих PNG, eslint вспомогательных скриптов, полный npm run check с typecheck/lint, 655/655 unit-тестами в 82 файлах и production build. Сохранилось прежнее предупреждение Vite о большом Phaser chunk. Git diff --check завершился с exit0. SHA256 всех 440 защищённых файлов совпал до/после; ссылки отчёта проверены. Детали в work/validation.json. Просмотрены реальные PNG обзора и Canvas screenshot. Новый E2E не запускался: игровой код и ресурсы не менялись. Механики, hitbox, баланс, фазы и прежние материалы сохранены. Commit, push, merge и deploy не выполнялись.

Остаётся неидеальным:в маленьком mobile-масштабе мелкие корни и отдельные швы сливаются;32цвета упрощают слабые грани;центральный меч закрывает часть табарда. Стойка намеренно спокойная,с опущенным клинком. Точный наклон low top-down и степень массивности требуют финальной художественной оценки на листе. Наличие correct PNG и успешных тестов не заменяет эту оценку.

Рекомендация:основной вариант годится как production-like статичная база для следующего этапа после пользовательского south idle approval. Перед анимацией понадобится выделить согласованные слои меча,двух кистей и корпуса с сохранением общей опоры. Следующая последовательность:сначала ручная приёмка south idle,затем directions/attack pack. Автоматически эти работы не начинаются.
