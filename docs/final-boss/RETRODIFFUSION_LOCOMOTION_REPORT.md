# RetroDiffusion locomotion — Ash Warden Stage 1

Дата: 2026-11-06. Ветка **main**, без переключения ветки и Git-операций записи.

**Stage 1 не завершён: производство остановлено на проверке South-пилота.** Получены South Idle и два кандидата South Walk. Первый Walk не делает шагов, второй двигает ноги, но меняет стойку/детали персонажа и плохо замыкается. Эти результаты не приняты как production locomotion. Остальные направления не генерировались согласно pilot-first; полный набор четырёх направлений не заявляется.

Каждый prompt и квитанция сохранены в [manifest.json](../../art/generated/ash-warden-locomotion-rd-01/manifest.json). Idle требует минимального дыхания, неизменного двуручного низкого хвата и неподвижных стоп. Первый Walk подробно требует тяжёлого преследования, чередования ног и сохранения оружия. После отсутствия шага prompt сокращён до прямого описания полного лево-право цикла: подъём/перенос/постановка одной ноги, перенос веса и смена опоры. Увеличено число кадров6→8, цена осталась той же. Это не контролируемый эксперимент только одной переменной: изменены текст и длина клипа.

Оригинальный128×128 спрайт вставлен в192×192 на(32,32) без масштабирования/редизайна. Прозрачный companion сохранён, API передан отдельный непрозрачный серый#808080 вход. Его контейнер — PNG RGBA, все alpha255. Исходный PNG не менялся.

Это калибровка по базовому корпусу, не заявление о точном анатомическом размере каждой изменившейся позы. Индивидуальное масштабирование, центрирование по bbox и перемещение кадров для сокрытия дрейфа не применялись.

Все18 PNG — **RGBA8,192×192,alpha0/255**, прозрачность присутствует, касаний краёв0. Лучший Walk bbox по всем кадрам x37..146/y30..156: запас полей достаточен. Бинарная alpha и свободные поля не делают анимацию принятой.

GIF извлечён Chromium ImageDecoder с учётом disposal; полные исходные серверные GIF сохранены отдельно. Локальной ретуши, палитризации и изменения порядка кадров нет. Серверный GIF уже изменил цветовую детализацию относительно44-цветного источника: Idle29 цветов на кадр, первый Walk27–29, повтор25–31. ## Визуальная проверка

| Критерий | South Idle | South Walk, лучший повтор |
| --- | --- | --- |
| Идентичность/масса | Узнаваемый тяжёлый Страж | Узнаваемый, но корпус/стойка заметно меняются по циклу |
| Шлем/визор | В целом стабилен, мелкая пиксельная дрожь | Разворот и форма видимых плоскостей/визора меняются |
| Наплечники/ветви/корни | Небольшие изменения контуров | Меняются проекция плеч и рисунок ветвей/корней; требуется фиксация ключевых форм |
| Руки/двуручный хват | Обе руки у одной рукояти, кисти тесно сливаются | Оружие не исчезает и явной свободной руки нет; непрерывная читаемость двух кистей не достигнута |
| Меч/гарда | Низкая стойка сохранена, кончик смещается | Меняются ширина/проекция клинка и положение гарды относительно рук |
| Стопы/перенос веса | Стопы почти фиксированы; это уместно для idle | Во втором варианте шаг появился, но контакт и возврат к исходной постановке недостаточно согласованы |
| Flicker/morphing | Мелкие детали дрожат, ткань меняется заметнее дыхания | Изменения брони/ткани и стойки мешают стабильному pursuit |
| Loop | На3→0 заметен сброс ткани/меча, нужно закрыть цикл | На7→0 скачок позы/шага; не бесшовная ходьба |
| Обрезание | Нет | Нет |
| Игровая читаемость | Различим на desktop/mobile | Шаг различим, но стабильная тяжёлая поступь и отсутствие скольжения не достигнуты |

Проверялись **все кадры**, несколько циклов в viewer и переход последнего к первому. Метрики frame-metadata.json включают bbox, цветность, фиксированные ROI и разницу соседних кадров. На шве меняется63.1% пикселей объединённого силуэта Idle и89.2% повторного Walk. Это **диагностика**, не самостоятельная оценка: показатель реагирует на сдвиги и даже небольшие изменения цвета. Решение основано также на просмотре поз, оружия, стоп и циклического движения.

У первого Walk низ стоп в фиксированных ROI остаётся y153/y149 на всех6 кадрах. Это вместе с визуальным просмотром подтверждает отсутствие походки. Эти ROI не являются автоматическим трекером ног: во втором Walk стопы выходят из первоначальных областей, поэтому его контакт оценивается визуально, а не по неверной привязке ROI.

[viewer.html](../../art/generated/ash-warden-locomotion-rd-01/viewer.html) — автономный локальный артефакт, с viewer-data.js рядом; открыть файл в браузере. В production UI его нет.

Настоящие Playwright screenshots сделаны на **1280×720** и **844×390**. Zoom2 desktop и1.2769230769 mobile одинаков для Mage, static и кадров. Статичные comparison sheets имеют те же размеры. Фон — crop существующего Burning Grove из sword-right-active-1280.png; движущийся фон viewer пересчитывается из screen-space crop в world scale. Это визуальный стенд, не новая игровая сцена Phaser.

Проверены2 цикла Idle при2FPS, затем3 цикла Walk при6.667FPS/72world units/s и3 при13.333FPS/144world units/s на каждом viewport. Пауза, scrub, шаги кадров, переключение клипа и увеличение темпа работают, JS ошибок и сетевых запросов нет.

**Согласование походки со скоростью не достигнуто.** При исходных1.2s на цикл скорость72 означает86.4world units движения за цикл; контактные позы не дают убедительного соответствующего шага. Удвоение скорости и FPS сохраняет ту же дистанцию за цикл и не исправляет контакт/шов. Автоматическая формула rate от скорости пока не утверждена: на текущем исходнике она создала бы ложную уверенность в отсутствии скольжения. Игровой FINAL_BOSS.speed=72 не менялся.

## Расход и граница продолжения

Каждый платный запуск предварён estimate_inference_cost с его prompt/input/размером/числом кадров. Запуски start_inference_job проверялись через get_inference_job, после завершения — get_balance. Ошибок MCP и платных повторов после timeout нет.

| Операция | Оценка при оплате с баланса | Фактически USD | Starter get_balance | Квитанция job |
| --- | ---: | ---: | ---: | ---: |
| До этапа | — | — | 91% | — |
| South Idle4 | $0.14 | $0.00 | 89% | 88% |
| South Walk6 | $0.14 | $0.00 | 87% | 86% |
| South Walk8 retry | $0.14 | $0.00 | 85% | 84% |
| Итог | $0.42 условно | **$0.00** | **−6п.п.** | минимум −7п.п. |

Баланс **$10.00→$10.00**, billing.source=plan, balance_charged=0. Денежный эквивалент использования Starter API не сообщает; $0.42 — не фактическое списание. Сохранены обе расходящиеся моментальные величины квоты. При принятии решений учитывался меньший job snapshot. Оба лимита соблюдены: менее$2.00 и не более10п.п.; квота не вырабатывалась до конца.

Причина остановки — **качество South-пилота**, не исчерпание денег. Даже при достаточном остатке не следует размножать текущие дефекты на другие направления. Не запрашивается увеличение бюджета для обхода этой проверки. До четырёх направлений/восьми клипов ещё остаётся существенная работа.
