# Encounter Director 2.0

2026-11-02. Ветка `feature/encounter-director-2`, исходная версия `57eb439`
(Combat Balance 2.0). Игра, карты, персонажи и умения сохранены. Push, merge
и deploy не выполнялись.

## Фактически выполненное расписание

Детерминированный прогон seed12345 вызывает настоящий EncounterDirector.
Участники предыдущего события убиваются между минутами, поэтому слоты свободны.
Это проверка исполнения расписания, а не доказательство естественной прокачки
или выживаемости с начала забега. Исходные записи: [EVENTS.json](EVENTS.json).

|---|---:|---:|---:|
| 3:00 | 1 | 0 | 0 |
| 4:00 | 0 | 1 | 0 |
| 5:00 | 1 | 0 | 0 |
| 6:00 | 0 | 1 | 0 |
| 7:00 | 2 | 0 | 0 |
| 8:00 | 0 | 2 | 0 |
| 9:00 | 3 | 0 | 0 |
| 10:00 | 3 | 0 | 0 |
| 11:00 | 3 | 3 | 0 |
| 12:00 | 3 | 3 | 0 |

После 10:00 означает начиная с 11:00: в 10:00 назначаются только три босса.
Первый тип — Charger, в 5:00 Sorcerer, в 7:00 Charger + Eclipse, с 9:00 —
все три типа. Назначение участников происходит в одном update.

Лимиты: 3 босса и 3 Guardian одновременно. Заполняются только свободные места.
Незанятая часть текущего запроса пропускается, повторной попытки внутри минуты
нет. Живые противники сохраняются. Следующая минута создаёт новый запрос.
Скачок времени выполняет только текущее последнее событие, без воспроизведения
пропущенных волн. Журнал ограничен 32 событиями, отложенной очереди нет.

Проверка занятых слотов: в 11:00 все шесть мест заняты — появилось 0 + 0,
пропущено 3 + 3. После убийства одного босса и одного Guardian в 11:01
немедленной замены нет. В 12:00 появились 1 + 1, пропущено 2 + 2. Старые
идентификаторы живых противников сохранены. [OCCUPIED_SLOTS.json](OCCUPIED_SLOTS.json).

## Измеренная агрессивность

Множители вычисляются из номера запланированной боссовой волны и базовых
характеристик. При занятых местах уже живые боссы получают текущие множители.
HP, damage и базовый `enemy.speed` не перемножаются повторно. Текущий видимый
телеграф сохраняет свой deadline при смене волны.

| Время | Movement | Cooldown frequency | Измеренная скорость C/S/E, px/s | Атак за 60 s C/S/E |
|---|---:|---:|---|---|
| 3:00 | 1.00 | 1.00 | 24.00 / 18.00 / 30.32 | 11 / 11 / 10 |
| 5:00 | 1.15 | 1.25 | 27.60 / 20.70 / 34.87 | 12 / 13 / 12 |
| 7:00 | 1.30 | 1.50 | 31.20 / 23.40 / 39.42 | 14 / 15 / 14 |
| 9:00 | 1.45 | 1.75 | 34.80 / 26.10 / 43.97 | 14 / 17 / 15 |
| 10:00+ | 1.60 | 2.00 | 38.40 / 28.80 / 48.51 | 15 / 18 / 16 |

C/S/E — Charger/Sorcerer/Eclipse. Скорость измерена настоящим `updateBoss`
на дистанции 400 px за 50 ms. У Eclipse сохраняются радиальная и боковая
составляющие 1 и 0.6, поэтому длина его шага больше `enemy.speed`.
Атаки — реальные переходы AI в windup за 60 s при удерживаемой дистанции 190 px.
Снаряды/метки очищаются в этом изолированном измерении, выживаемость не оценивается.
Данные: [BOSS_MEASUREMENTS.json](BOSS_MEASUREMENTS.json).

| Параметр | 3:00 | 10:00+ |
|---|---:|---:|
| Начальное ожидание всех боссов | 2 s | 1 s |
| Charger recovery / cooldown | 1.6 / 2.6 s | 0.8 / 1.3 s |
| Sorcerer recovery / cooldown | 1.8 / 2.6 s | 0.9 / 1.3 s |
| Eclipse I recovery / cooldown | 2 / 3 s | 1 / 1.5 s |
| Eclipse II recovery / cooldown | 2 / 1.5 s | 1 / 0.75 s |

| Предупреждение Eclipse | 1.25 s | 1.25 s |
| Вторая volley Eclipse II | 0.6 s | 0.6 s |

Частота действительно делит recovery и cooldown. Полный цикл ускоряется меньше,
чем номинальные ×2, поскольку предупреждения и активные атаки не сокращаются.
Charge сохраняет 400 px/s, 0.65 s и соответствующую телеграфу дистанцию 260 px.

Базовое HP из Combat Balance 2.0 не менялось: Charger 4500, Sorcerer 5700,
Eclipse 7200, Guardian 5400. Прежнее масштабирование HP по времени сохранено;
на 10-й минуте это 6525 / 8265 / 10440 / 7830 соответственно.

## Несколько Guardian и ограничение наград

- Отдельные enemy ID, HP, hurt/death-анимации и Map состояний по ownerId.
- Пробуждение от принятого урона или приближения на 64 px. Позиция неподвижна.
- Автоматический spawn: минимум 240 px от героя, вне viewport с padding 56 px,
  минимум 160 px между Guardian; максимум 48 попыток поиска позиции.
- Первые awakening смещены на 0 / 0.65 / 1.3 s. Warning луча 0.6 s,
  вращение 1.4 rad/s, длительность 2.8 s и recovery 1.5 s сохранены.
- У каждого свои три метеора с warning 1.4 s, radius 20–32 px и ownerId.
  Общий предел impacts + zones остаётся 24.
- Миникарта отображает все три независимых маркера; публикация остаётся 5 Hz.
- Leash фиксируется при активации с учётом диаметра группы + 220 px. Убийство
  соседа не уменьшает границу оставшегося активного Guardian. Реальный уход
  за неё или исходный abandonment/timeout завершает только соответствующий бой.
- Убийство одного удаляет только его луч, метки, снаряды и зоны. Смерть героя,
  рестарт и scene shutdown очищают все состояния. Пул visual corpses ограничен 3.

Одна фактически появившаяся группа Guardian даёт один случайный постоянный
артефакт **текущего забега** после убийства всех её участников. Артефакт выдаётся
автоматически, не теряется из-за заполнения физических drop slots. Каждый
Guardian независимо приносит 40 XP и 500 очков. Повторный callback не даёт
дополнительной награды. Уход одного участника срывает артефакт именно этой группы,
не уничтожая остальных. Неполная по свободным местам группа считается по реально
назначенным участникам; пустая группа не создаётся.

Старые группы 4:00 и 6:00 не сливаются с новой группой 8:00: каждая имеет свою
единственную награду и свой прогресс. Это не награда за каждого из трёх одновременно
живых Guardian. Если достигнуты все 15 stacks (3 каждого вида), новые Guardian
продолжают появляться и давать XP/очки, но новый артефакт не превышает прежние caps.
Исключение явно показывается в UI. Бонусы по-прежнему сбрасываются в новом забеге.

## Читаемость и обычные волны

Короткие уведомления различают Boss Encounter, Guardian Encounter,
Multi-Boss Encounter и Endgame Encounter. Они не останавливают игру.
UI показывает текущие группы Guardian, число побеждённых и правило одной награды.

При трёх крупных активных угрозах скрываются декоративные elite overlays и
плавающие числа урона. HD-тела элит, реальные tells Rusher/Caster и все
предупреждения боссов/Guardian сохранены. После снижения числа угроз украшения
и числа возвращаются. При событии с четырьмя и более крупными участниками
на 8 s действует 75% обычной частоты спавна, затем исходная частота возвращается,
даже если крупные противники ещё живы. Уже живые обычные мобы не удаляются;
их HP и предел 150 сохранены.

## Реальная выживаемость после 10:00

Среда замеров: Windows x64, Ryzen 5 7500F (12 logical CPU), 32 GiB RAM,
Node 22.16.0, локальный headless Chromium. Геометрия мобильного viewport
не эмулирует производительность физического телефона.

Один реальный Phaser RAF-прогон на условие, seed12345. Mage39: Fireball V,
Frost I, Lightning IV, Meteor II, Shield I, 38 легальных улучшений; три damage
артефакта представляют сильный возможный результат прежних трёх Guardian-волн.
Нет тестовой неуязвимости, отключения входящего урона или подстановки лечения.
Работают обычные Shield, i-frames, loot и Blink с CDR. Дополнительные уровни
не усиливают фиксированный билд. Пилот читает реальные телеграфы и двигается
обычным input через World.step; при опасности использует обычный Blink.

## Проверки и оставшаяся ручная оценка

`npm.cmd run check`: TypeScript, lint, **240 unit-тестов / 41 файл** и production
build успешны. Предупреждение о размере существующего Phaser chunk (1.387 MB
до gzip) остаётся; оно не скрывалось. Найденное регрессией перекрытие героя
мобильной колонкой артефактов/Guardian исправлено; отдельные 5 UI E2E прошли.

Отдельный survival E2E: **4/4**, 4.7 min. Production после исправления UI:
**4/4**, 28.6 s.
Основная dev-матрица: **117/117**, 16.7 min на окончательном коде. Четыре
новых real HP сценария выполнены отдельным survival-прогоном (4/4), поэтому
повторный прогон исключал только их. Всего выполнены **121/121 dev E2E**;
отключённых или оставленных непроверенными тестов нет. После survival менялся
только мобильный UI, игровая логика не менялась.

Фактические команды (разные локальные порты задавались через PIXEL_E2E_PORT):

```powershell
npm.cmd run check
npm.cmd run test:e2e -- tests/e2e/encounter-survival.spec.ts
npm.cmd run test:e2e -- --grep-invert 'real HP Mage39' --max-failures=3 --reporter=list --output=.tmp/e2e-director-regression
npm.cmd run test:e2e:production
```

Итоговые logs/.last-run.json остаются локально в .tmp. Локальный сервер для
ручного теста: http://127.0.0.1:5194/ . Git main остаётся57eb439, новые изменения
на feature/encounter-director-2. Push, merge и deploy не выполнялись.

Unit-тесты покрывают расписание 3–12, реальные assignments, caps, занятые места,
coalescing скачков времени, ограниченную историю, коэффициенты и реальные шаги/
атаки всех AI, обе фазы Eclipse, сохранение предупреждения, proximity, три луча/
метеора, общий артефакт, ошибочный повторный callback, достижение artifact caps,

Нагрузочные E2E удерживают 150 regular + 3 boss + 3 Guardian на обеих геометриях
для двух героев. Неуязвимость применяется **только** в этих структурных/performance
fixtures, чтобы удержать одинаковую нагрузку, а не для оценки выживаемости.

Остаются ручная оценка одновременных атак и общего TTK Guardian-группы, обычная
прокачка первых 10 минут, другие сборки/seed, Warrior в длинном endgame,
физические Android/iOS/highDPR и длительный heap/VRAM soak. После проверок
разработка останавливается для пользовательского игрового теста.
