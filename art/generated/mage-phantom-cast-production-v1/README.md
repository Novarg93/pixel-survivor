# Arcane Phantom Cast — игровая реализация

[Открыть игру](http://127.0.0.1:5173/) · [64 игровых сочетания](comparison.html)
· [Принятый анимированный пилот](../mage-phantom-cast-pixellab-v1/viewer.html).

Один общий Phantom Cast используется для Fireball и обычной Chain Lightning
**только в боковом/заднем секторе, включая границы ±90°**.
У него восемь ракурсов цели и двенадцать индивидуально заданных длительностей,
340 мс, one-shot. Отдельных fire/lightning анимаций фантома нет.
На каждом направлении движения три передних ракурса используют прежние native
анимации основного корпуса, остальные пять — фантом. Для NORTH обычные N/NE/NW,
фантомные W/SW/S/SE/E. Поддержаны все8×8 сочетаний, run-start/loop/stop и смена
движения внутри жеста без сброса его времени. Стоя используется обычное полное тело.

Ноги Mage сохраняют обычный Run и foot pivot. В переднем секторе существующий
верхний кастующий корпус разворачивается к цели максимум на45°, в фантомном
секторе основной Mage сохраняет полный Run.
Фантом — отдельное изображение только верхней части тела. Он фиксирует направление
реального события заклинания, следует за плечами текущего тела и исчезает сам.
Северные проекции рисуются за телом; остальные — поверх. Ноги фантома не экспортируются.
Поворот проявления выбирает текущую исходную и промежуточную directional-позу,
поэтому принятый North → East → South сценарий работает и в остальных сочетаниях.

Общий короткий жест не перезапускается при близких событиях Fireball/Lightning
и не размножается по числу снарядов/отскоков. У него отдельный канал без очереди,
поэтому длинная анимация Meteor не задерживает фантом. Старые отложенные события
body queue не воспроизводят проекцию повторно. Hurt, Blink, смерть и ультимейты
прерывают/подавляют её; пауза замораживает тот же World.elapsed.

Это слой представления: World, AI, targeting, spells, damage, cooldowns, movement,
mobile controls и механики Blink/Ultimate не изменены. Удар/снаряд по-прежнему
возникают в исходное игровое время. Кадр release в150мс обозначает косметическую
вспышку жеста; он не вводит задержку реального снаряда или урона.
Nova, Meteor, Shield и три ультимейта используют прежние body animations.

Визуальный старт Fireball фиксируется у текущей руки и плавно возвращается
на исходную collision trajectory (до240мс, короче для близких целей).
Первая дуга обычной молнии следует за анимированной рукой; остальные звенья и все
точки назначения сохранены. Руки размечены по существующим native PNG, у фантома
используются его actual palm metadata и позы проявления. Если hurt/Blink подавляет
жест, новый автокаст всё равно стартует у физической руки. World projectiles,
урон, кулдауны и реальное игровое время выпуска не меняются.

## Арт и источники

Принятый South сохранён byte-identical из PixelLab Pilot V1, включая native PNG
и Aseprite. Семь остальных направлений изготовлены через `animate_with_skeleton_v3`
по настоящим approved directional first frames Mage v2. Это ракурсы одного
empty open-palm gesture, без новых дизайнов и без отдельных заклинательных костюмов.

Первый North output разворачивался лицом на кадрах03–11 и отклонён:
`raw/north-rejected-turn/`, `comparisons/north-rejected-turn-raw.png`.
Исправленный North сохраняет спину. В Aseprite стабилизирована оригинальная голова,
удалены ноги, оформлены нижний край, контур и редкие частицы. У North на05 кадре
исправлен смазанный фрагмент кисти пикселями06, а северное смещение уменьшено,
чтобы поднятая ладонь сохраняла отступ от края. Raw output не перезаписывался.

Файлы:

- `reference/`: восемь точных утверждённых Mage views.
- `requests/`, `generation-manifest.json`, `raw/`: запросы без private URLs,
  все восемь генераций с rejected North и receipts.
- `processed/<direction>/00.png`…`11.png`:96 native256×256 RGBA кадров.
- `sources/<direction>.aseprite`:8 редактируемых источников по4 слоя.
- `gif/<direction>.gif`:8 one-shot GIF,12кадров/340мс каждый; палитра и бинарная
  прозрачность GIF ограничены форматом, RGBA PNG/runtime — источник качества alpha.
- `manifestation/`:16 самостоятельных исходных directional-поз проявления.
- `comparisons/`:контактные листы raw и восьми release-поз.
- `source-audit.json`, `validation.json`: source/pixel hashes и проверки экспорта.
- `actual-expenses.json`: фактическое списание и консервативная оценка бюджета.

Runtime: один `public/assets/hd/mage-phantom-v1/atlas.png/json`,1024×316,
1 294 336 RGBA bytes (~1.23MiB),112 frame keys/97 уникальных изображений.
Из native256 применяется один фиксированный nearest-neighbour переход в112,
такой же, как у настоящего тела Mage. Пустой alpha trim сохраняет полный canvas112
и shoulder anchor(56,28), per-frame bbox fitting/масштабирования головы нет.
Native256 остаются в editable art. Это не поворот одного плоского PNG в runtime.

## Проверка и воспроизведение

```powershell
node scripts/build-mage-phantom.mjs
node scripts/inspect-mage-phantom.mjs
npm.cmd run check
npm.cmd run test:e2e -- mage-phantom.spec.ts
```

Сборка повторяема, не вызывает PixelLab. Исходная генерация отдельно:
`prepare-directions.mjs` намеренно запрещает перезапись существующего paid ledger;
`collect.mjs` забирает готовые jobs; `prepare-processing.mjs` готовит аргументы
для `process.lua`, который запускается Aseprite MCP batch с save=false на копии
референса. Не перезапускать платные запросы ради сборки.

Проверены реальные игровые Canvas:desktop1280×720 и mobile landscape844×390 —
все64 movement/target сочетания для ОБОИХ spells:24native/40phantom на каждый экран
и spell. Всего256кастов. Отдельно проверены реальные первые кадры автокастов у руки,
движущаяся первая дуга, неизменённые отскоки и fallback при получении урона.
Screenshots/JSON в `screenshots/mage-phantom/` проекта. Проверены смешанный
Meteor+Fireball+Lightning, непрерывный Run, pause, Blink/hurt/death,10 restarts.
Общие casting/hero/run-cycle E2E сохраняют проверки остальных анимаций и ультимейтов.
Native/export validation:96 кадров,112atlas keys, partial alpha, отсутствие ног,
min3px до края, точная реконструкция RGBA и byte-identical South.
273 защищённых файла domain/original assets совпадают с baseline пилота.
Полный check после коррекции секторов:931unit/112files,typecheck/lint/build PASS.
Повторная сборка четырёх outputs byte-identical; все8GIF декодированы Chromium,
comparison.html загрузил64/64изображения по HTTP и file:// без ошибок.
Подробности новой разметки и матрицы: `../mage-cast-sectors-v2/`.

В игровом mobile масштабе мелкие пальцы остаются малозаметны. Поворот проявления
короткий, как в принятом пилоте; северная ладонь уходит вверх в перспективе.
Исходный пилот оставлен самостоятельным архивом приёмки. Ветка main,
commit/push/deploy не выполнялись.
