# Pixel Survivor — пакет для автономной разработки с Codex

## Перед запуском
1. Создай НОВУЮ пустую папку, например `C:\Users\Novarg\Desktop\PixelSurvivor`. Не распаковывай пакет в работающий Laravel-проект (`133-date` и другие).
2. Распакуй сюда содержимое ZIP, так чтобы `run-stages.ps1`, `PLAN.md`, `AGENTS.md`, `tasks/` и `docs/` находились в корне.
3. Проверь `node --version`, `npm --version`, `git --version`, `codex --version`, авторизацию `codex` и доступ к npm. Для лучшего результата подключи Playwright MCP и один раз протестируй его до автономного прогона.
4. Прочитай `run-stages.ps1`, `AGENTS.md` и разреши только доверенные SessionStart hooks (например Postman) в интерактивном Codex до ночного запуска, если они требуются. Ненужные плагины лучше отключить.
5. Убедись, что Windows не переходит в сон во время работы от сети, а диск имеет достаточно свободного места. Экран может выключаться, компьютер должен оставаться включённым.

## Запуск
Открой PowerShell в НОВОЙ папке игры:

```powershell
.\run-stages.ps1
```

Если PowerShell блокирует запуск подписей скриптов, после проверки содержимого можешь использовать в отдельном процессе:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-stages.ps1
```

**Важно о безопасности:** runner использует `codex exec --sandbox workspace-write --ask-for-approval never`. Это не отключает sandbox, но необходимые сетевые операции Codex может не выполнить. Установка npm-пакетов производится самим runner в обычном пользовательском контексте ПОСЛЕ создания `package.json` на этапе 00, с `--ignore-scripts`. Если нужны lifecycle scripts, проверь их до разрешения. НЕ используй `--yolo` и не запускай этот пакет в каталоге с чужими проектами или секретами.

## Как работает
- Инициализирует локальный Git-репозиторий, если его нет, и последовательно запускает 12 отдельных `codex exec` с reasoning=high. Коммиты и push автоматически не выполняются.
- Каждый проход читает `PLAN.md`, текущую задачу, `AGENTS.md` и `docs/PROGRESS.md`.
- После каждой стадии runner проверяет наличие `docs/done/NN.done` и выполнение `npm run check`.
- При ошибке делает до 3 попыток, затем безопасно останавливается. Не гарантирует сутки беспрерывной работы из-за лимитов, ошибок, решений политики безопасности, отсутствия сетевого доступа, проблем npm, и т.п.
- Повторный запуск пропускает стадии с marker-файлом. Если меняешь код выполненных стадий вручную, обязательно запусти `npm run check` и проверь лог.
- Логи: `codex-logs/stage-XX-attempt-Y.log`, прогресс: `docs/PROGRESS.md`.

## После выполнения

```powershell
npm run dev
npm run check
npm run build
```

Открой локальный адрес Vite. Для визуальных проверок и тестирования во время работы Codex может понадобиться Playwright MCP или отдельный Chromium для Playwright E2E. Проверку фактического FPS необходимо делать в браузере на реальном устройстве.

## Что НЕ входит
Laravel, авторизация, глобальный рейтинг, золото, монетизация, реальные платежи, сезонная система. Это следующая отдельная итерация после проверки основного геймплея.

## HD Pixel Art

В `feature/hd-pixel-art` выбранный стиль B используется по умолчанию, включая production.
Подключены Warrior, росток и его элита, Dark Forest, Cleave, тени и анимации.
Остальные ассеты продолжают работать в исходном виде до отдельных художественных задач.
Переключателя A/B/C нет. Материалы эксперимента сохранены в `experiment/visual-styles`.

Направление и размеры: [ART_STYLE_GUIDE.md](docs/ART_STYLE_GUIDE.md).
Очередь переработки: [ART_ROADMAP.md](docs/ART_ROADMAP.md).
Результаты и сравнение FPS: [HD_INTEGRATION_REPORT.md](docs/HD_INTEGRATION_REPORT.md).
Единый каталог: `src/game/art/assetRegistry.ts`. PNG и кадры: `public/assets/hd/core.*`.
Runner Pack 01 добавляет `public/assets/hd/runner.*`: 3 idle / 6 walk / 3 hurt /
6 death, две стороны, рамка 64×64 и прежний мировой размер 16×16.
[Отчёт Runner и скриншоты](docs/RUNNER_ART_PACK_01.md). Другие виды в этом пакете не перерисовывались.

На Windows используй `npm.cmd run check`, если execution policy блокирует `npm.ps1`.
Проверки этой рабочей копии можно изолировать: `$env:PIXEL_E2E_PORT='5185'`, затем
`npm.cmd run test:e2e`. Для production используй свободный порт, например `5186`.
