# План последующей переработки графики

Направление B зафиксировано в [ART_STYLE_GUIDE.md](ART_STYLE_GUIDE.md).
Эта ветка интегрирует только уже выбранный небольшой набор. Ни один из следующих
этапов не считается начатым или выполненным без отдельного задания и приёмки
интеграции пользователем. Нумерация ниже — художественные пакеты, не этапы
исходного PLAN.md и не основание для создания `docs/done/NN.done`.

## Общий контракт каждого задания

До рисунка выбрать один небольшой набор, перечислить `AssetId` из реестра,
зафиксировать имеющиеся display-размеры, pivot, состояния и число кадров.
Изменяются изображения/визуальное представление, не баланс или столкновения.
При необходимости новый размер исходника компенсируется `logicalSize` и
`worldScale`; World не должен импортировать art-модули.

Каждая поставка включает:

- Оригинальные PNG/atlas и редактируемый авторский источник либо описанный
  воспроизводимый процесс; соседние исходные проекты не затрагиваются.
- Записи `assetRegistry.ts` со статусом `hd-integrated` только для реально
  подключённых ресурсов. Честные `legacy`/неподготовленные clips у остальных.
- Idle/walk/hurt/death по требуемому пакету, одинаковый pivot и направление света.
- Сохранение игровых идентификаторов, семантики угроз, rarity, damage timing,
  XP, физического лута, радара, pause/restart и local storage.
- TypeScript, lint, unit, build, существующие E2E; дополнительные содержательные
  проверки на новый контракт. Тесты не удаляются ради зелёного результата.
- Настоящие Playwright PNG 1280×720 и 390×844, тесная группа и нагрузка 150 мобов.
  Для магии — главный импульс и затухание, для боссов — windup и recover.
- Проверка network/TextureManager: загружается только нужный набор, нет
  старых заменённых текстур, накопления чанков/объектов/слушателей/таймеров.
- Отчёт по FPS/frame time/CPU и текстурному бюджету с тем же harness и устройством,
  включая отличие test-only настроек от обычной игры. Художественные ограничения
  и нерешённые проблемы перечисляются отдельно.

Один пакет должен быть обозримым и пригодным к откату. Изменения логики, если
когда-нибудь понадобятся, выделяются в другое задание с отдельной мотивацией.
Не объединять девять пакетов в один большой рефакторинг.

## Первое последующее задание: обычный runner

Рекомендуемая первая небольшая проба после приёмки интеграции:

1. `AssetId: runner`, исходная мировая рамка 16×16, default scale 1;
   существующая элита временно использует прежний масштаб 1.4 и исходные метки.
2. Новый оригинальный кадр 64×64 и согласованные walk/hurt/death; не рисовать
   одновременно танка, стрелка и нового героя.
3. Закрепить наклон вперёд/длинные конечности и тёплый акцент, чтобы runner
   отличался от мшистого grunt без чтения цифр.
4. Подключить через текущий реестр и asset pack. Убрать только его заменённые
   legacy-текстуры после валидации, не грузить два полных варианта в production.
5. Проверить смешанную толпу из grunt/runner, элиту runner, контакт и смерть,
   150 мобов, оба viewport и перезапуск. Подтвердить отсутствие изменений ENEMIES.
6. Показать результат и отчёт; дальнейшие пакеты не запускать автоматически.

## Технические расширения по необходимости

Сейчас достаточно одного статического атласа `hd-core` и детерминированного
генератора леса. `hdCoreLayout.ts` описывает раскладку готового исходника;
`core.json` — фактические кадры для Phaser. Приёмка следующего пакета может
заменить PNG/manifest без изменения игровых систем.

Не вводить заранее сложный загрузчик тем, переключатель арт-стилей, CDN,
глобальный art store или отдельный анимационный таймер. Если новые наборы
перестанут помещаться в малые атласы, добавить явные asset packs по назначению
и грузить необходимые в preload сцены; перед этим измерить память/загрузку.
Атласы не должны пересоздаваться при каждом перезапуске забега.

Death-анимации в будущем потребуют ограниченного визуального пула трупов/эффектов;
это не повод сохранять мёртвую сущность в списке активных врагов или задерживать
начисление XP/лута. Размер и время пула проектируются в отдельном пакете.

## Известные вопросы для художественной приёмки

- Короткие текущие циклы B показывают направление, но не финальную покадровую пластику.
- В Dark Forest плотная фактура травы местами шумит; снизить её можно на этапе 6,
  сравнивая читаемость, а не меняя координаты троп/декора.
- На mobile исходное уведомление о пробуждении Guardian может частично перекрывать
  его голову при определённом положении камеры. UI не менялся в интеграции;
  проверить размещение уведомлений в пакете 9 и на настоящем телефоне.
- В этой интеграции нет замера реального телефона или длительного VRAM soak.
  Для массовой графики это отдельный критерий аппаратной проверки.

Полная переработка начинается только после проверки и принятия текущей интеграции.
