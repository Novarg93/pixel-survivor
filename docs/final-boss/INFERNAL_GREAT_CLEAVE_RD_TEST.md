# Infernal Great Cleave — тест RetroDiffusion south/front

Дата: 2026-11-06. **Частичный результат: production-like критерии полностью не пройдены.** Выбрана попытка2: связный overhead cleave вперёд получен, но постоянство клинка, кистей и деталей модели требует ручной доработки. Это best test attempt, не художественно утверждённый pack. Следующий шаг — исправление cleave в Aseprite и повторная приёмка, до Charge/Meteor.

По прямому решению пользователя работа продолжена с RD-базой, несмотря на прежнюю рекомендацию PixelLab. Другие генераторы не использовались.

## Что получено

- 2 генеративных попытки, по12 кадров каждая; финальный выбранный клип — **12 кадров**,192×192 RGBA PNG.
- Исходные серверные GIF, полный набор PNG обеих попыток, strip, sheet, nearest×4.
- GIF выбранной попытки и интерактивное HTML-превью с pause/play и покадровым scrub.
- Сравнение static RD + кадры0/4/6/11 + Mage на Burning Grove, desktop1280×720 и mobile844×390.
- Порядок кадров и исходные150 ms/кадр сохранены: **1.8 s**. Ретуши, перестановки, удаления кадров и изменения темпа нет.

Разметка фаз выбрана после просмотра результата, не является гарантированным управлением генератором:

| Фаза | Кадры, 0-based | Наблюдение |
| --- | --- | --- |
| Windup | 0–5 | Начальная стойка, подъём к груди, затем над головой;900 ms |
| Release / Impact | 6–8 | Резкий переход в низкий вертикальный удар к screen bottom, затем удержание;450 ms |
| Recovery | 9–11 | 9 ещё удерживает инерцию,10–11 возвращают диагональную стойку;450 ms |

Разбиение6/3/3 отличается от примерного4–5/3–4/3–5, общий объём остаётся12. Оно отражает фактические позы. В первой попытке полноценной такой разметки нет: почти весь клип — подъём меча.

## Вход и параметры

Основа: [best-candidate.png прошлого RD-теста](../../art/generated/ash-warden-retrodiffusion-01/best-candidate.png), оригинальная попытка1,128×128. Холст расширен до192×192, спрайт вставлен в(32,32) **без масштабирования и изменения пикселей**. Сохранён прозрачный companion; API получил непрозрачную серую подложку#808080. Это только подготовка входа, не новый дизайн. PNG companion с суффиксом rgb непрозрачен; canvas сохраняет контейнер RGBA.

Прежняя оценка тела111 px и scale72.68625/111=**0.6548310811** сохранена для всего клипа; опора padded-источника(96,154). Тело базы соответствует2.73Mage при Mage26.625world px. Кадры не нормализованы отдельно по bbox: это скрыло бы дрейф размеров и поз. Увеличенный bbox impact объясняется мечом, его не трактуем как рост корпуса.

До запуска: get_balance, list_available_models, list_available_styles(tab:advanced-animation); перед каждым выбранным стилем get_style_usage, перед каждой генерацией estimate_inference_cost. Обе анимационные схемы требуют input_image, допускают32–256 px, не поддерживают reference_images. Актуальные идентификаторы взяты из MCP.

Первый длинный prompt с покадровыми указаниями дал только подъём меча. Для второго изменены только режим на custom_action и описание движения: кратко потребовано **одно полное действие**, подъём → немедленный прямой downward slam → низкое удержание → возврат. Основа и seed сохранены. Точный лучший prompt: [prompt-best.txt](../../art/generated/ash-warden-cleave-rd-01/prompt-best.txt). Оба полных запроса и квитанции: [generation-record.json](../../art/generated/ash-warden-cleave-rd-01/generation-record.json).

Запускался start_inference_job с последующим get_inference_job. Оба задания завершились succeeded, повторных платных вызовов при ожидании не было. В квитанциях result.model=**rd_fast**, а стили относятся к **RD Animation Advanced**. Это фактическая маркировка сервера; тест не называется RD Pro-анимацией. Согласно каталогу custom_action создан совместно с PixelEngine. Выбора отдельной модели поверх prompt_style схема не предоставляет.

Допустимые frames_duration и GIF-выход проверены также в [официальных примерах RetroDiffusion](https://github.com/Retro-Diffusion/api-examples/blob/main/example-scripts/05_animation.py).

## Результат проверки качества

| Проверка | Вывод по лучшей попытке |
| --- | --- |
| Полный action cycle | Да: подъём → прямой удар → возврат; заметно лучше attempt1 |
| Направление | Удар по вертикали вперёд к зрителю; кругового вращения/широкого сектора нет |
| Вес | Медленный подъём и низкое удержание помогают; переход5→6 слишком скачкообразный, не хватает проходной силовой позы |
| Стабильность модели | Частично: персонаж узнаваем, ноги визуально устойчивы; на3–5 теряются наплечники/ветви и меняется рисунок корпуса |
| Двуручный хват | Обе руки сходятся к общей рукояти, явной свободной руки нет; на3–6 кисти сливаются, читаемость всех ключевых кадров не достигнута |
| Цельный тяжёлый меч | Сохраняется один меч, но меняются ширина, длина, угол гарды и узор разломов; на4–5 клинок менее массивен, на6–9 вытянутый и узкий |
| Усиление оружия в release | Длинная вертикальная форма есть, убедительного усиления массы нет; толщину и переход надо править |
| Силуэт и ветви | Базовая масса узнаваема; верхний замах местами похож на обычного более узкого рыцаря, ветви пропадают/меняют рисунок |
| VFX | Длинный огненный след/разлом не нарисован, место под Phaser VFX оставлено; на6 есть отдельные светлые точки над головой |
| Desktop/mobile | Направление удара видно на обоих масштабах; отдельные кисти на mobile неразличимы, тёмная броня местами сливается с грунтом |
| Recovery/seam | Возврат есть, но финал не равен исходной позе пиксель-в-пиксель; на циклическом переходе остаётся небольшой скачок |

Чтение движения подтверждено последовательностью кадров и работающим воспроизведением; VFX не добавлялись для маскировки дефектов. Удар выглядит как заготовка overhead cleave, но **строгий тест стабильности рук/клинка и production-готовности не прошёл**. С точки зрения генерации основы для Aseprite результат полезен; напрямую использовать его как финальный action pack преждевременно. Исправления потребуют работы с ключевыми позами, не только очистки одиночных пикселей.
