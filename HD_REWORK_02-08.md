**Назначение:** единственный управляющий документ для Codex, который последовательно завершит весь оставшийся художественный рефакторинг Pixel Survivor, не переписывая игру.

**Статус исходной работы:** художественный пакет 01 (Runner / Ember Strider) уже выполнен; в основной проект ранее интегрированы Warrior, Grunt, элитный Grunt, Dark Forest, Cleave и базовые тени. Перед работой проверить фактическое состояние Git и `assetRegistry.ts`: отчёт — это ориентир, а не доказательство состояния файлов.

**Уровень рассуждений Codex:** **High** для всего плана; **Extra High**, если доступен и нужен при сложной интеграции анимаций/ресурсов. Не переключать модель автоматически, если настройка недоступна.

**Охват:** ровно семь последовательных пакетов — **02, 03, 04, 05, 06, 07, 08**. Вместе с уже готовым пакетом 01 это восемь художественных пакетов. Никакого нового Laravel, аккаунтов, оплаты, платных усилений, ребаланса или новых игровых механик.

## B. Инварианты для всех пакетов

### B1. Чего нельзя менять

- `World`, игровые сущности, HP, броню, скорость, урон, cooldown, hitbox, collision radius, I-frames, RNG, генерацию волн, XP, бафы, артефакты, таблицу очков и баланс — без отдельного технически необходимого обоснования. Визуальная анимация не может задерживать игровую смерть/дроп/очки.
- Значения `logicalSize`, `worldScale`, `origin/pivot` для существующих сущностей сохраняются; если изменился размер PNG, компенсировать его исключительно в визуальном слое. Разделять размеры исходного кадра и мировые размеры.
- `World` не импортирует `art`/Vue-модули. Vue не обновляет каждого врага каждый кадр. Визуал читает существующие события и состояния симуляции.
- Читаемость вражеских телеграфов, иконок редкости, радарных маркеров и системных уведомлений важнее красивых частиц.
- Существующие игровые бюджеты и ограничения остаются прежними (реальные значения перепроверить в актуальном коде): до 150 обычных врагов, 3 боссов, 1 Guardian, 96 снарядов, 240 XP и 96 эффектов, а также лимиты лута и временных визуальных объектов.
- Никаких скачанных/скопированных спрайтов Hades, Death Must Die, Children of Morta и др.; новые PNG и редактируемые исходники должны быть оригинальными. Нельзя выдавать программный прототип за профессиональную ручную живопись.
- Никакого параллельного изменения `main`, старого экспериментального worktree или соседних репозиториев.

### B2. Исходное качество и художественный контракт

- Направление — **оригинальный dark fantasy HD Pixel Art**, не пиксельное размытие и не механическое масштабирование 16×16 PNG в 64×64.
- Художественная база и палитры — **`docs/ART_STYLE_GUIDE.md`**, включая свет сверху-слева, NEAREST, бинарную альфу для пиксельных спрайтов, стабильный pivot, читаемые силуэты и мировые размеры.
- Приоритет: **силуэт → различимость в реальном размере → ключевые материалы → анимационная пластика → декоративные пиксели**.
- На экранном масштабе zoom 2 и на 390×844 новый ассет должен быть видимо лучше старого. Неподтверждённая «HD»-метка запрещена.
- Сохранять читаемость цветов угроз, лечение/бафы/XP/артефакты не должны выглядеть как декор фона.
- Использовать существующие авторские генераторы/атласы, `assetRegistry.ts`, `GameArt` и существующий pipeline. Добавлять пакеты по необходимости, не строить абстракции «на будущее».
- Излишний блум/шейдеры, полноэкранные фильтры, сотни отдельных GameObjects на частицы и дублирование атласов в production запрещены.

### B3. Git и восстановление

До первого изменения:

1. Выполнить `git status --short --branch`, `git log -5 --oneline`, проверить `git worktree list`, `git remote -v`; убедиться, что это Pixel Survivor.
2. Если есть незакоммиченная работа пользователя или другого Codex, **не удалять, не сбрасывать, не прятать молча через stash**: объяснить риск в `docs/hd-rework/BLOCKERS.md` и остановиться.
3. Если рабочая директория чистая, создать рабочую ветку `feature/hd-art-rework-02-08` от актуального локального `main` (или использовать уже существующую рабочую ветку с тем же назначением). Если `main` занят другим worktree, не переключать его насильно; создать новый worktree, либо сообщить безопасную команду.
4. После **каждого принятого по автоматическим критериям пакета** сделать локальный коммит, если не запрещено более строгими инструкциями AGENTS.md. Пример: `art: complete hd pack 02 mage grove and spells`. **Не выполнять push или merge в main**.
5. Разрешено остановиться на блокере без коммита. Не коммитить логи с секретами, `node_modules`, тестовые профили Chromium, временные файлы или чужие каталоги.

Один пакет = обозримый и независимый Git checkpoint. Если коммит невозможен, сохранять полные сведения в отчёте и не изображать его выполненным.

### B4. Контракт проверки КАЖДОГО пакета

1. Прочитать актуальные `AGENTS.md`, Art Guide, реестр, код и требования пакета; зафиксировать **список затрагиваемых AssetId** и исходные logical/display размеры, pivot, clips, fps и источники.
2. Снять исходный baseline **до изменений**, если это реалистично: фиксированная сцена и одинаковый seed; не сравнивать разные условия как эквивалентные.
3. Реализовать только текущий пакет, написать/обновить данные реестра; `hd-integrated` только если реальный ресурс подключён. Устаревшие `legacy`-текстуры заменённых объектов не должны загружаться в production.
4. Запустить `npm.cmd run check`, `npm.cmd run test:e2e`, `npm.cmd run test:e2e:production`, `git diff --check`; при отсутствии команды установить причину, не заменять отчёт фиктивным результатом. Использовать порт E2E, не конфликтующий с работающим dev-сервером.
5. Реальный Chromium + Playwright: снять **PNG игрового Canvas**, а не только DOM. Для каждого значимого набора — 1280×720, 390×844; смешанная сцена и стресс-плотность до 150 мобов. Для нового бойца — кадры idle/walk/hurt/death, для магии — начало/пик/затухание, для боссов — windup/attack/recovery. Лично просмотреть полученные файлы визуальным инструментом; если это недоступно, честно указать, что просмотр не состоялся.
6. Проверить старт нового забега, pause/resume, 10 restart/scene restart, отсутствие роста TextureManager keys, GameObjects, pooled corpses, чанков, listeners, таймеров, Canvas; отсутствие console/pageerror/404/неожиданных внешних запросов.
7. Для производительности использовать **одинаковый сценарий, hardware, renderer и viewport**. Записывать FPS, p95 frame time, p95 Scene.update, источник RGBA-бюджета, число atlas/texture keys и видимых GameObjects. FPS≈60 при 60 Hz не доказывает равную GPU-стоимость; viewport телефона на ПК — не реальный телефон. Результаты «до/после» не выдумывать.
8. Не ослаблять существующие asserts, не удалять тесты и не подменять реальные E2E только unit-тестами. Не допускать длительных неконтролируемых stress-прогонов.
9. Написать `docs/hd-rework/PACK-XX.md` с фактами, ограничениям и ссылками на скриншоты, обновить `docs/hd-rework/PROGRESS.md` и `docs/PROGRESS.md`; только затем отметить завершение в `docs/hd-rework/done/XX.done`.
10. Если художественный результат явно слаб (не читается на основном масштабе, нет реальных кадров, ассет не отличим от legacy), исправить в пределах пакета либо зафиксировать как **не завершено**, остановиться. Не маркировать успех по формальному числу кадров.

### B5. Структура прогресса и артефактов

```text
docs/hd-rework/
  PROGRESS.md                 # один актуальный источник состояния
  BLOCKERS.md                 # только реальные блокеры
  PACK-02.md ... PACK-08.md   # отчёты по пакетам
  FINAL_REPORT.md             # сводка после пакета 08
  done/
    02.done ... 08.done      # создавать только после тестов
screenshots/hd-rework/

```

Создать `PROGRESS.md` с таблицей: `pack`, `status` (pending/in_progress/verified/blocked), `branch`, `commit`, `changes`, `checks`, `screenshots`, `limitations`, `next`. Наличие `.done` не заменяет проверки: если код изменился позже, перепроверять.

## ПАКЕТ 02 — Mage HD, Grove HD и все пять способностей Mage

**Цель:** оба игровых героя, обе базовые локации и все способности мага выглядят в одном HD pixel-art стиле. **Пакет первый в очереди.**

**Промпт:**

> Реализуй художественный пакет 02 из `HD_REWORK_02-08.md` полностью. До изменений изучи текущий `Mage`, `Grove`, `GameArt`, atlas/re registry, все пять магических умений и эффекты. Сними baseline. Никаких изменений игровой логики, XP, speed, spawn, collision, damage, ability timing и баланса.
>
> **Mage:** оригинальный набор с отчётливой шляпой/лицом/магическим фокусом, отдельными видимыми фазами idle (2–4), walk (минимум 4), hurt (2–3), death (4–6). Направления up/down/side, допустимое зеркалирование только если не портит силуэт. Утверждённый логический размер героя **24×30 мировых единиц**, origin `(0.5, 0.75)`; реальный контракт перепроверь в реестре. Корректные pivot, единое направление света и чёткий контраст с обоими биомами. Death-клип не должен задерживать смерть/награды.
>
> **Grove:** переработай процедурные тайлы и декорацию в HD pixel art: светлый, но всё ещё dark fantasy; цветовая тема отличается от холодного Dark Forest. Сохраняй исходные world-координаты, размеры чанков, механику spawn, детерминированность, texture cleanup. Новые кусты и свечение не могут походить на лут, врагов, предупреждения или XP. Без видимых швов и повторяемой громкой фактуры.
>
> **Fireball:** HD-ядро, читаемый шлейф, контактная вспышка/взрыв и затухание. **Frost Aura:** не перекрывающие врагов ледяные кольца, пульсация, корректная индикация slow/freeze, если логически реализована. **Chain Lightning:** отчётливые связи уникальных целей, красивое короткое затухание без рисования сотен отдельных объектов. **Meteor:** предупреждение, падение, удар и остаточная зона только если она существует в World. **Arcane Shield:** читаемая защитная сфера и момент срабатывания/импульса. Каждая способность должна визуально усиливаться при уже существующих рангах/эволюциях без добавления урона.
>
> Уточни исходные `AssetId`, не угадывай имена. Для переменных размеров AoE/дистанций использовать реальные данные World, а не визуальную константу, меняющую hitbox. Все пять эффектов оставить совместимыми с существующим cap и очисткой. Заменённые legacy Mage/Grove/mage spell textures не загружать в production.
>
> Добавь точечные unit/E2E на frame selection/pivot, Grove seams/determinism, visual timing, реальный запуск всех пяти умений, Mage в обоих биомах, pause/restart и 150 мобов. Сними before/after PNG desktop/mobile, отдельные кадры эффектов. Запусти общий B4 quality gate. Запиши отчёт, сделай локальный checkpoint и **автоматически переходи к пакету 03**.

**Приёмка:** Mage и Grove явно лучше legacy в реальном масштабе; у всех пяти умений минимум один качественный видимый эффект и правильное затухание; World не меняется; все проверки зелёные.

## ПАКЕТ 03 — оставшиеся способности Warrior + общий Game Feel

**Цель:** все пять способностей воина и базовые реакции на удары выглядят единым HD-набором, без изменения игровой силы.

**Промпт:**

> Реализуй пакет 03. Используй уже HD Cleave как стилевой эталон, но не перерисовывай его без причины. Изучи фактические `AbilityId` и существующие эффекты/эволюции.
>
> **Whirlwind:** читаемые вращающиеся дуги и динамика оружия с ограниченным числом спрайтов, ясно видимая фаза старта и завершения. **Ground Slam:** короткое предупреждение/подготовка, ударная волна, пыль, трещины (чисто визуальные) и fade; сохранён прежний радиус и момент попадания. **Bladestorm:** различимые вращающиеся клинки и шлейф без сотен самостоятельных GameObjects. **Iron Skin:** выразительный защитный материал, начало действия и ясный момент окончания/срабатывания, не закрывает здоровье и хит-эффекты. **Cleave:** только согласование оттенков/света с новыми способностями, если требуется.
>
> Добавь/доработай **общий визуальный feedback**: краткий hit flash, умеренные hit sparks, ограниченная пулом death анимация/частицы, опциональный локальный shake только для реально мощного удара. Соблюдай доступность: возможность уменьшить интенсивность, без постоянной тряски/белых вспышек; не ломай существующие настройки. Вражеский warning — поверх дружественной магии.
>
> Все обновления рисуются по времени симуляции/существующему render loop; не добавляй самостоятельные интервалы/RAF. Не трогай hit stop на уровне симуляции и не задерживай приёмы ввода. Выровняй визуальные признаки повышения ранга уже существующих Warrior spells, но не создавай новых механик.
>
> Добавь E2E всех четырёх новых HD-способностей и Cleave, их основные фазы/затухание, crowd scene, screenshot desktop/mobile, проверку порядка слоёв, pool cleanup и 10 restart. Запусти gate B4, отчёт, локальный checkpoint; **переходи к 04**.

**Приёмка:** герой способен самостоятельно применять все пять умений; они визуально различимы в плотной группе, эффекты не изменяют World и не превращают 150-мобную сцену в нечитаемое свечение.

## ПАКЕТ 04 — все оставшиеся обычные противники

**Цель:** закрыть остатки legacy среди обычных врагов. Runner и Grunt уже HD, их не переписывать.

**Промпт:**

> Реализуй пакет 04 в следующей внутренней очереди: **Tank → Caster → Charger/Rusher (реальный ID уточнить в коде) → Splitter**. Для каждого типа завершай собственный микроцикл: ассеты → registry → визуальная проверка → тест. Не приступай к следующему виду, пока предыдущий визуально читается. Сохрани существующий `RunnerAnimation`/death pool как референс, переиспользуй подход, но не создавай монолитный новый manager.
>
> Для каждого типа: исходник/атлас с авторскими кадрами, согласованные направления и origin, idle 2–4, walk минимум 4, hurt 2–3, death 4–6. Если по игровому дизайну конкретный тип не движется обычным шагом, подбери эквивалентные выразительные фазы, не меняя AI. Реальный source size можно подобрать в соответствии с Art Guide; **logicalSize/worldScale неизменны**.
>

## ПАКЕТ 05 — HD-элиты и Rare Guardian

Сохраняй относительные display sizes, hitbox, elite-multiplier и game IDs. Подготовь корректные idle/walk/hurt/death или переиспользуй базовые клипы с индивидуальными HD-накладками, если в игровом размере это художественно убедительно и registry честно это фиксирует.
>
> **Rare Guardian:** отдельный оригинальный HD-персонаж, **необычный для толпы**: неподвижный массивный облик, солнечная/каменная тема, заметная грудная печать, не путать с элитной короной. Достаточно выразительных idle/hurt/death, если Guardian действительно неподвижен. Сохраняй исходные мировые размеры/радарный золотой маркер, положение спавна, обнаружение, HP, контакт и гарантированный артефакт. Устранить визуальную проблему, при которой уведомление Guardian на 390×844 перекрывает его голову, **только UI-позиционированием**, не меняя логики.

## D. Когда считать весь художественный рефакторинг завершённым

- **Не менее семи пакетов** `02–08` имеют реальную проверку и запись `verified`; каждый этап имеет свой отчёт, скриншоты и изменения в Git.
- В `assetRegistry.ts` нет ложного `hd-integrated`; видимые legacy-объекты либо закрыты, либо перечислены в `FINAL_REPORT` как оставшаяся работа с объяснением.
- Существующие tests/unit/E2E/production проходят, `git diff --check` чистый.
- Читаемость интерфейса и событий доказана реальными Canvas-скриншотами, а не только DOM и цифрами FPS.
- Никаких изменений gameplay-статистики в рамках художeственного рефакторинга без отдельного одобрения; если обнаружена неустранимая архитектурная зависимость, остановиться и описать blocker.
- Ветка готова для review/merge, но **в `main` никто автоматически не вливает и на GitHub не отправляет**.

### Ручная проверка пользователем после финала

```powershell
# В рабочей папке ветки feature/hd-art-rework-02-08
npm.cmd run check
npm.cmd run test:e2e
npm.cmd run test:e2e:production
npm.cmd run dev
```

Провести хотя бы один живой забег за Mage и Warrior на обеих картах, посмотреть спавн элит, Guardian, boss telegraphs, экипировку/скиллы, миникарту и Game Over. Отдельно проверить реальный телефон: Playwright desktop viewport **не** является мобильным железом.

## E. Как возобновить, если Codex остановился

Отправить в новой сессии Codex из **той же рабочей директории**:

> Продолжи художественный рефакторинг Pixel Survivor строго по `HD_REWORK_02-08.md`. Сначала прочитай `docs/hd-rework/PROGRESS.md`, реальные `docs/hd-rework/done/*.done`, `git status` и последние локальные коммиты; затем перепроверь, какой пакет действительно завершён. Не повторяй готовые изменения, не перезаписывай пользовательские данные. Начни с первого незавершённого пакета; выполни все оставшиеся до 08 с теми же тестами, отчётами и ограничениями. Не останавливайся после промежуточного отчёта. Не выполняй push/merge/deploy.

**Важная честная граница:** одна большая интерактивная сессия не гарантирует работу «всю ночь». Для автоматического продолжения после завершения процесса нужен отдельный контролирующий запускатель; этот документ обеспечивает сохранение контекста, но сам не запускает новый Codex-процесс.
