# Mage — четыре варианта упрощения

9 ноября 2026 · изолированный concept pass · выбор пока не сделан.

Открыть [viewer.html](viewer.html) двойным щелчком или через dev-server:
`http://127.0.0.1:5173/art/generated/mage-style-exploration-v1/viewer.html`.

- **A — Наследник:** знакомый сине-зелёный образ, открытое лицо, длинная одежда без золочёной филиграни.
- **B — Капюшон:** выраженный силуэт мага, крупные массы тёмного плаща, меньше информации на лице.
- **C — Боевой маг:** короткая одежда и отчётливые ноги; хорошая основа для последующей проверки бега.
- **D — Пепельный плащ:** светлая накидка, сдержанный зелёно-синий цвет, широкие складки.

Все четыре — оригинальные статичные PNG 96×96 с прозрачностью, один front/south ракурс. Это варианты дизайна для выбора, **не готовые наборы направлений/анимаций**. Top-down перспектива и межракурсная стабильность ещё требуют side/north proof у выбранного образа. Маг не заменён в игре.

## Референс и исправление

Используется **актуальный игровой Ash Warden**, а не ранний `art/final-boss/ash-warden-base-final.png`. После замечания пользователя пример исправлен: `references/ash-warden.png` восстановлен из действующего `src/game/art/ashWardenManifest.json`, `south-idle`, кадр 0, без phase3 overlay. В `references/ash-warden-runtime-source.json` сохранены frame ID, atlas page, pivot, scale и hash RGBA. Свежий `references/ash-warden-in-game-current.png` снят в настоящем бою через кнопку «Бой со Стражем» и обычное управление; runtime-код не менялся.

Meteor C и Flame Strike C показаны отдельными локальными кадрами. Briar Beast — дополнительный принятый минибосс, не автоматическая подмена художественного имени Hound. Для будущей production-задачи точный принятый Hound-исходник следует закрепить в brief.

Попытка отправить ранний reference PNG в PixelLab была отклонена автоматической проверкой до исполнения. Все четыре успешных запроса выполнены **только по тексту**, без исходного арта и без обхода ограничения. Принятые референсы используются лишь для локального сравнения.

## Поставка и воспроизведение

- `originals/a.png` … `d.png` — неизменённые PNG из inline image-результатов PixelLab `get_image`.
- `requests.json` — полный общий prompt, различия дизайнов, seeds, job/source image IDs и параметры.
- `results.json` — завершённые jobs, asset IDs и фактический расход; приватных URL/ключей нет.
- `metrics.json` — размеры, alpha, bounding boxes, цветовой счётчик и SHA-256.
- `prepare.mjs` — локальная подготовка референсов из принятых файлов, audit и metadata viewer; **не генератор**, не меняет принятые ассеты.
- `viewer.html`, `viewer.js`, `viewer-data.js` — локальный просмотр без fetch/module/CDN, работает по file:// и HTTP.
- `screenshots/` — preview webpage/Canvas, общий лист, game-scale сравнение. Эти композиции не выдаются за игру с новым героем.
- `protected-baseline.json`, `protected-validation.json` — SHA-256 6583 существующих файлов `src`, `public/assets`, `art`, исключая этот новый staging-каталог.

Повторить локальную подготовку из корня проекта:

```sh
node art/generated/mage-style-exploration-v1/prepare.mjs
```

Успешных генеративных запросов **4**, по **5** единиц подписки: **20** всего, баланс **1626.90 → 1606.90**, денежных API-кредитов **$0**. Повторных генераций, новых ракурсов/анимаций и замены production-арта нет.

## Результат QA

PNG 96×96, отступы не менее 9 px до края, clipping отсутствует, alpha только 0/255. A/B/C используют 28 RGB-цветов, D — 20. Базовая проверка PNG encode/decode сохраняет RGBA. 6583 защищённых файла не изменены.

Условия масштаба в preview: текущая native модель имеет видимую высоту 222/256×40 = **34.6875 world px**. Для сравнения кандидатам назначается эта же видимая высота при camera zoom 2 и 1.28. Это только viewer, не новый scale в assetRegistry. Увеличенный лист использует одинаковый множитель ×3 для native PNG, без подгонки пропорций вариантов.

Полный `npm.cmd run check` прошёл: 112 unit-файлов, 931 тест, typecheck/lint/build. Лог: `.tmp/mage-style-exploration-v1/check.log`. Предупреждение Vite о размере chunks существовало до этого pass. Проверка viewer и screenshots записаны в `browser-validation.json`; production gameplay E2E для статичных концептов не запускались.

Следующий шаг: пользователь выбирает A/B/C/D или сочетание черт. Затем отдельный side/north и ключевые позы; полный комплект и интеграция — после приёмки образа.
