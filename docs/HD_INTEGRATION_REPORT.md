## Что интегрировано

Один утверждённый HD-атлас: `public/assets/hd/core.png` (109096 B),
`core.json` (6677 B), 1024×364, 37 кадров. PNG побайтно совпадает с B:
SHA256 `b418309e30600ba2a839995386ccf9e3575f3ac4db776c71780f2348a5b4bc4f`.
Warrior: down/up/side, idle 2 / walk 4 / hurt 2; росток и элита: по 4 кадра;
Cleave: 4 фазы; тень: 1 кадр. Dark Forest использует только генератор B,
чанки 256×256 с прежним мировым размером 128×128.

HD включён по умолчанию в dev и production. App.vue, игровой bridge и настройки
профиля не расширялись переключателем. A/C, их атласы, генераторы и UI не перенесены.
Заменённые старые Warrior/grunt не создаются. Остальные игровые изображения
пока исходные и явно отмечены `legacy` в `assetRegistry.ts`.
Массовая перерисовка не начата.

При настройке новых production-assertions обнаружены две ошибки самого учёта:

проверки отсутствия внешних запросов/лишних изображений не отключались.
После исправления весь production-прогон зелёный. Сборка также поймала
недостижимые legacy-ветки после удаления старого Cleave/леса; они удалены из
визуального кода, типы и тесты не подавлялись.

## Механики, коллизии, лут и радар

`git diff main` пуст для World, игровых abilities/config/entities, EnemySystem,
CombatSystem, loot, radar, UI и bridge. Изменены только представление, его каталог,
preload, генерация/чистка визуальных текстур и инструменты проверки.

Новые тесты подтверждают:

- На паузе полная сериализация World не меняется от работы представления.
- Warrior/Mage: 24×30 мировых единиц; обычный росток: 16×16; элита: 22.4×22.4;
  Guardian: 33.6×39.2. Размер исходника не назначает радиус столкновения.
- Настоящее движение выбирает walk; реальный контакт выбирает hurt.
  При неподвижном grunt на дистанции 20 урон отсутствует, на 18 — HP Warrior
  меняется с 150 на 141.8 по исходной броне, радиус врага остаётся 10.
- Настоящий автоматический Cleave наносит урон и создаёт HD-эффект.
- В кадре присутствуют Guardian, физический артефакт, расходник, сундук, XP,
  баф с таймером и маркеры радара; их источники и размеры сохранены.

Полный существующий набор дополнительно проверил реальные drop/contact/buff/
stack/expiry, магнит и XP, сундуки, редкого моба, неподвижность и обнаружение
Guardian, награду артефактом, 5 Hz радара, элит/боссов, смерть, результаты,
перезапуск и local storage. На built-версии обе пары персонажей/биомов
атакуют, ставятся на паузу, меняют размер и работают без внешних ресурсов.

## Загрузка и жизненный цикл

Production-запросы изображений/JSON в assets ровно:
`/assets/hd/core.png` и `/assets/hd/core.json`. A/C и переключателя нет даже
при `?visual=1`; `__PIXEL__` отсутствует в production.
Dev-диагностика TextureManager подтверждает единственный `hd-core` на 37 кадров,
нет `visual-study-*`, старых warrior-* и grunt/grunt-walk.

При четырёх повторных созданиях сцены атлас загружен всего один раз (два запроса:
PNG + JSON). В каждой нагрузочной пробе 150 grunts дают 151 тень с игроком.
На desktop при перемещении 0 → 2000 → −50000 → 0 стабильно:

| Счётчик | Значение |
|---|---:|
| Чанки | 48 |
| Текстуры, включая чанки | 85 |
| Постоянные текстуры без чанков | 37 |
| Scene children в фиксированной нагрузочной пробе | 353 |
| Активные/pending/removal Clock events | 0 / 0 / 0 |
| Tweens | 0 |
| BLUR listeners, включая исходные слушатели Phaser | 4, не растёт |
| commands / snapshots / metrics | 1 / 1 / 1 |
| DOM canvas | 1 |

После scene.restart тени возвращаются к одной, созданные объекты уничтожаются,
core переиспользуется. Источники TextureManager в такой desktop-пробе имеют
RGBA-оценку 14130960 B (~13.5 MiB); число не растёт с расстоянием и перезапусками.
Это сумма размеров источников, не измерение VRAM/heap/копий драйвера.
Данные: [resources.json](../screenshots/hd-pixel-art/resources.json).

## Производительность относительно исходного оформления

На **чистом рендерере main до подключения HD** запущен тот же сохранённый harness,
что затем на HD. Baseline: 2026-11-01T08:00:54.572Z, HD финального общего прогона:
2026-11-01T08:16:40.795Z. Chromium 156.0.8078.4, Ryzen 5 7500F, RTX 4060,
ANGLE/D3D11, около 31.6 GiB RAM, headless, DPR 1.

Одинаковая нагрузка: 150 grunts (2 элитных), 1 Guardian, haste на земле, сундук
и продлённый Cleave. Живые steering/collisions, 1 s прогрева + 6 s RAF sample
на viewport. Только тестом включена неуязвимость, отключены автоатаки и новые
естественные спавны, чтобы не уменьшалось число мобов. В обеих выборках минимум
и максимум regularCount = 150, Guardian = 1. Метрика mapped sprites = 153 в обоих
вариантах; у HD дополнительно рисуются тени и отдельный Cleave.

| Viewport | FPS исходный → HD | p95 frame, ms, исходный → HD | p95 Scene.update, ms, исходный → HD |
|---|---:|---:|---:|
| 1280×720 | ≈60 → ≈60 | 16.8 → 16.8 | 0.8 → 0.9 |
| 390×844 | ≈60 → ≈60 | 16.8 → 16.8 | 0.8 → 0.9 |

Наблюдаемого падения FPS на этом GPU нет; при ограничении около 60 Hz нельзя
утверждать равную стоимость. Разница 0.1 ms у короткой выборки не является
устойчивой статистической оценкой. Сохранён и исходный 60-секундный peak-wave
stress из существующей E2E-матрицы — он прошёл с новым основным рендерером.

Стоимость текстур выросла: HD-чанк 256² вместо 128² — 256 KiB вместо 64 KiB
RGBA-источника; на 48 чанках это +9 MiB до учёта драйвера. Сам core ~1.42 MiB
RGBA при ~106.5 KiB PNG в сети. Старые заменённые акторские текстуры убраны.
Память источников, время первоначального декодирования и слабые GPU нельзя
оценивать только по ровным 60 FPS. Начальная загрузка не входит в steady sample.

Сырые данные: [baseline-performance.json](../screenshots/hd-pixel-art/baseline-performance.json),
[hd-performance.json](../screenshots/hd-pixel-art/hd-performance.json).
390×844 — viewport того же desktop PC, не замер телефона.

## Ограничения и следующий шаг

Нет блокирующих технических ошибок. В captured console/pageerror массивы пусты;
рост отслеживаемых ресурсов не обнаружен. Длительный heap/VRAM soak, реальные
телефоны, высокий DPR и pixelScale 3 не проходили отдельную визуальную матрицу.
Отдельные death-клипы и финальная пластика B пока не изготовлены.

После приёмки интеграции пользователь может выдать первое небольшое задание
из [ART_ROADMAP.md](ART_ROADMAP.md); автоматически массовая перерисовка не запускается.

## Повторение

```powershell
npm.cmd run check
$env:PIXEL_E2E_PORT = '5185'
npm.cmd run test:e2e
$env:PIXEL_E2E_PORT = '5186'
npm.cmd run test:e2e:production
```

Baseline-флаг используется только тестовым процессом, не браузерным runtime.
Его сохранённый результат снят **до интеграции**: включение флага на HD-коде
меняет имя файла отчёта, а не возвращает старый рендерер. Для повторного baseline
нужен исходный main с тем же harness в разрешённой отдельной рабочей копии.
